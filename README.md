# The strategy vs you

A smallcase can have a strong strategy, but your actual return can still be different depending on when and how you implement it. **The strategy vs you** reconstructs what the smallcase would have done with your actual investments and rebalances, compares that with your real trades, and explains the difference. It also decomposes the performance over trades/ rebalancing event/ individual constituents, currently in the portfolio or held in past. Besides the LLM-powered explainability layer, this tool provides a unified view of performance data that is otherwise fragmented across multiple sources.

**Live app:** https://strat-vs-user.streamlit.app/

**Full writeup:** [Scope and Methodology (PDF)](https://dhruwanda.github.io/assets/pdf/smallcase_report_00.pdf)

## What it does

The analysis works in three steps:

1. **Reconstruct the model**  
   Uses the smallcase timeline and your investment history to determine what the model strategy would have performed with your money.

2. **Reconstruct your implementation**  
   Uses your Zerodha tradebook and P&L to determine what you actually did.

3. **Explain the gap**  
   Compares the model trades with your actual trades and attributes the difference to implementation effects such as price and quantity differences (modified orders).

The main output is:

**Model return on your money → Your return → Difference in percentage points → What caused that difference**

An **LLM-powered Q&A layer** sits on top of this analysis, allowing you to ask detailed questions about the results, constituent-level or trade-level granular analysis. For example, which stocks or trades contributed to the gap, or which rebalance had the most impact. The LLM explains and explores the results generated by the deterministic analysis; it does not calculate returns or attribution itself.

## Demo scenario

It simulates an investor who puts money into a smallcase, makes an additional investment later, and follows the smallcase's rebalances—but does not always execute them exactly as the model does.

The fictional strategy enters the smallcase **Gringotts Growth** with four equally weighted (25%) constituents on Jan 15. It makes 2 sequential investments.
- **Jan 15:** Start with **₹1 lakh**
- **Mar 10:** Add another **₹1 lakh**

It subsequently rebalances three times:
- **Jan 15:** **BUY** Albus, Bellatrix, Cedric, Draco
- **Feb 2:** **SELL** Draco → **BUY** Dobby
- **Mar 2:** **SELL** Albus → **BUY** Aragog
- **Apr 6:** **SELL** Bellatrix → **BUY** Buckbeak

Assuming the investor implements each rebalance **two trading days late**, creating (intentional) differences in the prices at which they are executed. These differences are what the **attribution engine** or the deterministic calculation layer breaks down. The demo also includes transaction costs, fees, and a dividend for a stock that the strategy never held, to test reconciliation and edge-case handling.

All data is fictional and generated by `make_demo.py`.

## Data

The app uses:

- **Smallcase timeline** — investment and rebalance history used to reconstruct the strategy.
- **Zerodha tradebook** — your actual buys and sells.
- **Zerodha P&L** — portfolio and realised/unrealised P&L information.
- **Dividends** — used where relevant to the portfolio reconciliation.
- **Price data** — used for deeper trade-level attribution.

The app fetches the required market prices automatically, working out the specific stocks and trading days the analysis needs rather than a complete daily price history for all constituents. A local `prices_cache.csv` is **only needed if that fetch fails** — run `fetch_prices.py` locally and upload the file it writes.

## Privacy

Uploaded tradebooks, P&L statements and price files are processed at runtime and are not stored anywhere as part of the repository.

## Run locally and deploy

```bash
pip install -r requirements.txt
streamlit run app.py
```

The app can be deployed on Streamlit Community Cloud with `app.py` as the main file.

The Q&A layer requires a Gemini API key. Locally, add it to `.streamlit/secrets.toml`; when deployed, add it under the app's Secrets settings.

```toml
GEMINI_API_KEY = "your-key"
```
