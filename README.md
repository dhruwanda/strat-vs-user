# The strategy vs you

A smallcase can have a strong strategy, but your actual return can still be different depending on when and how you implement it. **The strategy vs you** reconstructs what the smallcase would have done with your actual investments and rebalances, compares that with your real trades, and explains the difference.

**Live app:** https://strat-vs-user.streamlit.app/

## What it does

The analysis works in three steps:

1. **Reconstruct the model**  
   Uses the smallcase timeline and your investment history to determine what the model strategy would have performed with your money.

2. **Reconstruct your implementation**  
   Uses your Zerodha tradebook and P&L to determine what you actually did.

3. **Explain the gap**  
   Compares the model trades with your actual trades and attributes the difference to implementation effects such as price and quantity differences (modified orders).

The main output is:

**Model return on your money → Your return → Difference in percentage points → What caused that difference**

A **LLM-powered Q&A layer** sits on top of this analysis, allowing you to ask detailed questions about the results, constituent-level or trade-level granular analysis. For example, which stocks or trades contributed to the gap, or which rebalance had the most impact. The LLM explains and explores the results generated by the deterministic analysis; it does not calculate returns or attribution itself. 

## Demo scenario

It simulates an investor who puts money into a smallcase, makes an additional investment later, and follows the smallcase's rebalances—but does not always execute them exactly as the model does.

The fictional strategy holds four equally weighted (25%) constituents and starts with:

- **Albus**
- **Bellatrix**
- **Cedery**
- **Draco**

It subsequently rebalances three times:

- **Feb 2:** SELL Draco → BUY Dobby
- **Mar 2:** SELL Albus → BUY Aragog
- **Apr 6:** SELL Bellatrix → BUY Buckbeak

The investor implements each rebalance **two trading days late**, creating differences in both the trades made and the prices at which they are executed. The investor also makes an additional **₹1 lakh investment on Mar 10**.

The synthetic data is deliberately constructed so that these implementation differences create a meaningful gap between the model and the actual portfolio. This allows the attribution engine to demonstrate how the gap can be broken down into effects such as **price differences, quantity differences and subsequent price movements**.

The demo also includes transaction costs, fees, and a dividend for a stock that the strategy never held, to test reconciliation and edge-case handling.

All data is fictional and generated by `make_demo.py`; no real portfolio data is included.

## Data

The app uses:

- **Smallcase timeline** — investment and rebalance history used to reconstruct the strategy.
- **Zerodha tradebook** — your actual buys and sells.
- **Zerodha P&L** — portfolio and realised/unrealised P&L information.
- **Dividends** — used where relevant to the portfolio reconciliation.
- **Price data** — used for deeper trade-level attribution, required if automatic fetch fails.

## Price data

The app first attempts to fetch the required market prices automatically.

A local `prices_cache.csv` file is **only needed if the app is unable to fetch the required prices itself**.

If the automatic price fetch fails, run `fetch_prices.py` locally to obtain the required prices and upload the resulting `prices_cache.csv` to the app. The app determines the specific stocks and trading days required for the analysis rather than requiring a complete daily price history for all constituents.

## Privacy

Uploaded tradebooks, P&L statements and price files are processed at runtime and are not stored anywhere as part of the repository.

## Run locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

The Q&A layer requires a Gemini API key. For local use, add it to `.streamlit/secrets.toml`:

```toml
GEMINI_API_KEY = "your-key"
```

## Deploy

The app can be deployed on Streamlit Community Cloud with `app.py` as the main file.

Add `GEMINI_API_KEY` under the app's Secrets settings to enable the Q&A layer.
